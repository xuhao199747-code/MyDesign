# 共享顶部导航设计

## 背景

首页 `index.html` 与个人介绍详情页 `project.html` 都需要展示一致的顶部导航。当前两页各自维护一份导航 HTML，后续修改容易产生差异。

## 目标

- 首页与个人介绍页复用同一份导航结构。
- 保持当前 PC 导航的视觉样式与交互行为。
- 保持移动端菜单、滚动状态、微信入口和页面跳转行为。
- 个人介绍页从首页入口打开时，导航表现与首页一致。

## 方案

新增公共导航渲染模块，由两个页面各自提供导航挂载节点；模块统一生成导航 DOM，并继续调用现有的 `initSiteNavbar` 处理菜单开关、点击关闭、滚动状态与页面恢复。

导航链接根据页面上下文配置：

- 首页：简历、作品、微信入口、联系。
- 详情页：关于、作品、联系，并保留返回首页的品牌入口；如需与首页完全一致，则简历入口继续指向 `project.html?slug=profile`。

导航样式继续复用现有 `styles.css` 与页面已有 class，不引入新的 UI 框架或依赖。

## 范围

- 新增共享导航模块。
- 替换 `index.html` 与 `project.html` 中重复的导航结构为挂载节点。
- 接入两个页面的初始化入口。
- 验证 PC 和移动端导航显示、菜单开关与链接跳转。

不改动个人介绍页主体内容，不改动首页其他模块，不处理部署与后台配置。

## 验证标准

- 两个页面均能正常加载导航。
- PC 端导航布局与当前首页一致。
- 移动端菜单可打开、关闭，点击链接后自动收起。
- 进入 `project.html?slug=profile` 后导航链接仍然可用。
- 项目构建命令通过。
