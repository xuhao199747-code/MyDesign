# 取消访客 AI 对话次数限制

## 目标

取消访客达到配置次数后无法继续调用 DeepSeek 的限制，同时保留 `visitor_usage` 中的调用次数统计，方便后台继续查看使用量。

## 范围

- 修改 `api/chat.js`：不再根据 `api_call_count` 与 `apiLimitPerVisitor` 返回 `limit_reached`。
- 保留每次 DeepSeek 成功调用后的 `visitor_usage` 递增逻辑。
- 保留响应中的使用量信息；由于不再有实际上限，`remaining` 不再作为有效剩余次数展示。
- 不删除 Supabase 的配置字段、统计表或后台配置界面，避免影响已有数据和后台兼容性。
- 更新相关自动验证脚本，使其验证“超过原配置值仍能调用并计数”。

## 数据流

访客提问 → 读取配置和访客统计 → 调用 DeepSeek → 成功后递增调用次数 → 返回回答和累计调用次数。

简历意图和知识库命中逻辑保持不变，它们仍然不调用 DeepSeek，也不增加调用次数。

## 错误处理

DeepSeek 调用失败时继续返回现有错误，不增加调用次数。Supabase 读取或写入失败时继续走现有错误处理。

## 验证

- 自动验证：访客已达到或超过原上限时，聊天接口仍返回成功，并将调用次数递增。
- 自动验证：简历和知识库请求行为不变。
- 构建项目，确认页面和 API 相关代码没有语法或打包错误。
